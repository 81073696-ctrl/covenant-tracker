# 战绩统计：pick 率与通关率

这份文档说明「统计」页里的数字**是怎么来的、能信到什么程度、怎么把别人的记录合进来**。

---

## 1. 为什么没有「全服数据」

炉石有官方插件接口，TFT 有 Riot Match API，Overwolf 还能从客户端拿对局状态——所以那些工具的 pick/win 率是**有数据源的**。

卫戍协议没有：

- 鹰角没有开放战绩 API；
- 没有 Overwolf 那种合法的客户端数据通道；
- 网上只有攻略和主观强度榜（B 站、NGA、TapTap），没有带样本量的原始记录。

所以本项目的路线是 **本地记录 + 文件合并**：

```
每局结束 ──▶ var/matches.jsonl ──▶ 聚合 ──▶ 统计页
                    ▲
       导入别人的 JSONL（按 id 去重）
```

将来如果做社区汇总，只需要把「读本地文件」换成「拉服务器」，聚合代码一行不用改。

---

## 2. 一条记录里有什么

`MatchRecord`（`covenant/stats/model.py`），一行 JSON：

```json
{
  "id": "9f2c1a7b3d40",
  "ts": 1793988000.0,
  "mode_id": "mode_single_funny",
  "mode_name": "标准模拟",
  "band_id": "band_bldsk",
  "band_name": "华法琳",
  "patch": "act2autochess@2026-03",
  "rounds": 14,
  "total_rounds": 14,
  "hp_left": 9,
  "result": "clear",
  "cups": 12,
  "shop_level": 6,
  "gold_left": 3,
  "board": [{"op_id": "chess_char_1_01_a", "star": 2}],
  "bench": [],
  "bonds": {"lateranoShip": 4, "swiftShip": 3},
  "note": "",
  "v": 1
}
```

刻意只存**终局快照**：过程数据（每回合商店、每次刷新）体积大、噪声大，等真的需要复盘时再加。

`patch` 是 `数据包id@赛季`，用来把 11/8 前后的记录分开——数值改过之后，混在一起算会失真。

---

## 3. 三个数字的定义

| 指标 | 定义 | 为什么这样定 |
|---|---|---|
| **出场率 pick** | 该干员出现在**终局战场**的对局 / 筛选出的对局 | 整备区里买来又卖掉的过渡牌会把出场率灌水 |
| **通关率 win** | 带该干员的对局里通关的比例 | 卫戍是 PvE 合作，没有名次；「胜」= 结算通过 |
| **Δ** | 该干员通关率 − 全体通关率（百分点） | 玩家水平会整体抬高/压低胜率，看相对值更有意义 |

附加：

- **95% 区间**：Wilson 区间。样本少时区间会很宽，这是故意的——它在提醒你别当真。
- **最小样本**（默认 5）：出场次数低于它的行标灰，不下结论。3 场 2 胜的「66.7%」没有信息量。
- **阵容**：终局至少 2 条盟约才成组，按场次排序。

---

## 4. 偏差：这些数字不能当真理

1. **自愿上报**：样本 = 装了这个工具、还愿意点「记录本局」的人，不是全体玩家随机抽样；
2. **水平偏差**：强干员会被高手优先拿，胜率天然偏高；
3. **版本偏差**：数值/池子一改，旧记录就过期了——所以按 `patch` 过滤；
4. **单人视角**：多人局里队友的干员看不到，只记自己的终局阵容；
5. **中途退出**：`quit` 不计通关，但会计入对局数（否则会高估通关率）。

看趋势、看 Δ、看样本量；别把小数点后一位当真理。

## 5. 怎么用

### 记录一局

打完 → 切到「统计」页 → **记录本局** → 选结果（通关 / 失败 / 放弃）→ 有杯数就填 → 保存。

记录的是**当前面板上的终局状态**：所以打完别急着点「过回合」或「新局」，先把结果存了。

### 导出 / 导入

- **导出 CSV**：给 Excel 看，一局一行，UTF-8 BOM，中文不乱码；
- **导入**：选文件或直接粘贴 JSONL，按 `id` 去重，重复的会跳过；坏行会单独计数，不会让整批失败。

合并社区文件时，直接把别人发来的 `.jsonl` 拖进来即可。

### 筛选

模式 / 策略 / 赛季 / 最小样本，四个条件可以叠加。筛选结果只影响当前视图，不改文件。

## 6. 文件与接口

| 位置 | 说明 |
|---|---|
| `var/matches.jsonl` | 一行一条记录，纯追加；损坏的行会被跳过并计数 |
| `GET /api/stats?mode=&band=&patch=&min=` | 聚合结果 |
| `POST /api/match` | `{result, cups, note}`，把当前状态落成一条 |
| `GET /api/match/export?fmt=csv\|jsonl` | 导出 |
| `POST /api/match/import` | `{text}`，合并 JSONL |

写入用「临时文件 + `os.replace`」，中途崩了不会写坏原文件。
