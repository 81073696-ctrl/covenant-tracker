# 整体复查：这套东西现在是什么水平，下一步该修哪里

写于 v0.3（结算识别 + 按回合统计 + 社区收集器）之后。不是宣传页，尽量挑毛病。

## 1. 结构

```
capture ─→ vision ─→ state ─→ calc ─→ ui
   │          │         │        │      └─ 面板 / 教学页 / 统计页
   │          │         │        └──────── 卡池·概率·经济·盟约·聚合（纯函数）
   │          │         └───────────────── 绝对快照 + 动作/观测归约 + 时间线
   │          └─────────────────────────── 区域布局 · 数字模板 · 图标 NCC
   └────────────────────────────────────── PrintWindow/BitBlt / 文件夹 / 合成
```

**成立的地方**

- 每层都能单独替换：换采集源不用动识别，换识别不用动状态，换 UI 不用动计算；
- 计算层是纯函数，给定 `(pack, state)` 就有确定输出，测试好写；
- 状态是「绝对快照 + provenance」，识别错了直接改字段，不需要回滚事件流；
- 数据包外置，新赛季改 JSON 就能跑，不用等代码发版。

**不成立的地方**

- `state/reducer.py` 已经开始变长（买卖刷升 + 时间线 + 结算提示 + 观测处理），
  再往里塞「装备」「精锐角标」之前应该先拆成 `actions/` 与 `observers/`；
- `ui/server.py` 同时管路由、静态文件、快照缓存、采集源、token，后面加接口会继续膨胀；
- `teach.js` 是纯手写 DOM 操作，功能能跑但状态分散，改一处要读三遍。

## 2. 效率

实测（demo，1280×720 合成画面 / 空对局）：

| 指标 | 数值 | 说明 |
|---|---|---|
| `/api/snapshot` 首次 | 200，约 25 KB | 完整快照含概率表 |
| 重复请求 | 304，0 body | `ETag` + `If-None-Match`，按 `revision` 失效 |
| 轮询间隔 | 1.4 s | 页面隐藏时跳过 |
| 计算耗时 | 毫秒级 | 133 干员 × 6 阶，纯 Python |
| 依赖 | 标准库 + numpy + Pillow | 没有数据库、没有前端构建 |

还能再快，但**目前不是瓶颈**：真正的瓶颈是「一帧图要跑多少次模板匹配」。
每个商店格一次 NCC（48×64 归一化），5 格就是 5 次；干员有 130+ 个模板时，
最坏要全比一遍。优化顺序：

1. 先按等阶过滤候选（商店等级决定上限），候选从 130 降到 ~20；
2. 模板降到 32×40，先粗比再精比；
3. 识别频率降到「商店变化时才跑」，而不是每帧都跑。

## 3. 安全与边界

- 只读屏幕：`PrintWindow` / `BitBlt`，不碰游戏内存、不注入、不改客户端；
- 服务只绑 `127.0.0.1`，非回环要显式 `COVENANT_ALLOW_LAN=1`；
- CORS 只回显同源，预检只允许 `GET/POST/OPTIONS`；
- 收集器默认无 token，但只在本机；公网部署文档里强制要求 `--token` + HTTPS；
- 记录不含账号/设备/IP，收集器关掉了访问日志。

**没做的**：本机面板没有登录（同机进程都能调 `/api/action`），这在本机场景可接受，
但如果以后要做「手机看面板」，必须加一次性 token。

## 4. 准确性：哪些数字能信

| 数据 | 置信度 | 依据 |
|---|---|---|
| 干员/盟约/策略名单、等阶、价格 | 高 | 客户端表逆向，`data` |
| 商店格数、升级价（按模式分表） | 高 | `mode_single_funny` 实测 3/4/4/4/4/5、1/1/5/8/10/11 |
| 卡池份数 12/14/18/16/8/5 | 中 | 社区口径，标注 `community` |
| 抽卡均匀模型 | **低** | 官方未公布，行业惯例假设 |
| 收入 `min(3+r,10)` | 中 | 文档公式，FUNNY 额外加成标 `assumed` |
| 盟约阈值 | 中 | 从描述文本正则提取，可能有漏 |

结论：**池子余量和价格可以当参考，具体概率别当承诺**。11/8 之后第一件事是拿
真实商店刷 50 次，统计每个等阶出现频率，回来校准 `calc/odds.py`。

## 5. 统计的可信度

- 出场率只算终局战场，避免「买来过渡又卖掉」把数据灌水；
- 样本 < 5 标灰，给 Wilson 区间；
- 自愿上传 = 严重选择偏差（爱传的人更可能通关、更可能玩版本强势）；
- 单人视角看不到队友阵容，多人局的「干员出场」只代表自己；
- 结算识别只判通关/失败，**杯数要手填**（结算界面的杯数区域还没学模板）。

## 6. 优先级建议

1. **11/8 实测校准**：先保证不误导（价格/格数/收入），再谈概率；
2. **结算识别补杯数与最终等级**：现在只判 clear/fail，记录里杯数靠手填；
3. **商店候选剪枝**：识别从「全模板」变「按等阶候选」，这是效率最大的一刀；
4. **精锐角标 / 装备格**：直接影响卡池余量准确性（精锐占 3 份）；
5. **多人共享池面板**：队友拿走的份数现在只能手填 `rules.pool_extra`；
6. **打包**：`pyinstaller` 单文件 exe + 首次运行自动解包数据包，降低「装 Python」门槛；
7. **社区页**：把 `community` 的 HTML 做成正式排行页（现在只有前 10 的表格）。

## 7. 如果要做成「给别人用」的产品

最小可用路线：

```
单文件 exe（内含 packs/ + 前端）
   → 首次启动向导：选窗口 → 教数字 → 教 3 个商店格
   → 打完自动弹「记录本局」
   → 一键上传到你的收集器
   → 收集器出一个公开排行页
```

风险不在技术，在**数据口径**：一旦公开数字，就会有人拿它当「强度榜」。
所以页面必须同时显示样本量与置信区间，并且明确写「自愿上传，有偏差」。

## 自查：报告本身的问题（2026-11-07 13:30）

Kimi 的代码审查有 6 条结论，我按她的 `repro_bugs.py` 原样跑了 5 条，**全部不成立**。问题不在她的复现脚本，在报告的方法：

1. **快照错位**：报告标题写「审查快照 live-20261107-1228」，但描述的是 04:31 的行为。12:28 里「可靠性三项」（同局去重 / 账本失败隔离 / 等级未知跳过）已经合入。
2. **没有修后复跑**：5 条「建议必修」在 12:28 前已修，报告仍按旧结论写「必须修」，也没有在合并后的目录上重跑一次。
3. **严重度与影响面不匹配**：「重复记一条战绩」被写成数据污染，但统计口径是终局快照，重复只影响样本量，不改变单条记录内容。
4. **缺可核对定位**：没有函数名/行号/最小命令，复现完全依赖单独的脚本文件；报告和工作区一旦分开就无法自证。
5. **漏了真正的输入健壮性问题**：报告只测「功能路径」，没测「非法输入」，而服务端有几处 `int()` 直接把异常抛到 500。

### 自查发现并修掉的（这批不是她的）

| 问题 | 修法 |
|---|---|
| `set` 动作对 gold / round_no / shop_level / hp / upgrade_decay / bond_layers / bond_group 直接 `int(value)`，传 `"abc"` 抛 `ValueError` 逃出 reducer | 统一 `_as_int()` → `ActionError`（HTTP 200 + `ok=false`），旧状态不变 |
| `frozen` 用 `bool("false") == True` | 字符串按 `1/true/yes/on` 解析 |
| 核心盟约两组重叠时，选中组里的共享盟约被当成「另一组」禁掉 | `others - chosen` |
| `snapshot()` 里 `pool_snapshot` 与 `shop_odds` 各建一次池、各过滤一次干员 | `shop_odds(pool=…)` 接收已算好的池；snapshot 0.47ms/次 |
| 观测 `SHOP` 收到非列表（`5`）时 `for item in raw` 抛 `TypeError`，视觉噪声能把引擎打挂 | `dispatch()` 兜底 `TypeError/ValueError/AttributeError`，记日志不崩 |
| `add_unit` 接受未知 `op_id`、`star=99`；`sell/move/remove` 传未知区域名抛 `KeyError`；`move` 的 `to_slot` 裸 `int()` | 统一 `_zone()` / `_as_int()` / 星级 1..3 / 未知干员拒绝 |

### 结构
