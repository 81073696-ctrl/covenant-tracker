# 两人一机的协作约定

这个项目由两个 AI 在同一台 Windows 上协作：DeepSeek Harness（本会话）和 Kimi / Daimon。
两者没有共享上下文，靠**文件**当信箱。目标不是「谁听谁的」，而是让改动可核对、可回滚。

## 1. 分工

| 角色 | 更适合做什么 | 原因 |
| --- | --- | --- |
| 本会话（DeepSeek） | 采集/识别、UI、数据包、端到端、跑服务 | 能开窗口、抓帧、起 HTTP 服务、看截图 |
| 外部审查（Kimi） | 静态审查、边界条件、测试补强、文档校对 | 不依赖运行时，适合「读代码找茬」 |

同一条 bug 两边都可能发现；**以能复现的测试为准**，不按来源采纳。

## 2. 不要在线上目录并行改

外部审查请在自己的工作副本或独立分支上修改，
产出以下任意一种即可：

- 一份 `REVIEW-NOTES.md`：文件、行号、问题、建议改法、是否附测试；
- 一组 `*.patch` / `*.diff`（`git diff --no-index` 或手写 unified diff 均可用）；
- 直接改副本并在说明里列出「改了哪几个文件、为什么」。

不要多人同时写同一份工作副本——并行修改会互相覆盖；请通过分支、补丁和 PR 合并。
中文文件统一使用 UTF-8，修改前先确认编辑器编码。

## 3. 合并流程

0. 每轮收尾先跑 `python scripts/check_all.py --frames var/demo_frames`
   （编译 → 单测 → 前端语法 → doctor，一步失败即非零退出）；
1. 本会话先跑 `py -3 -m unittest discover -s tests`，确认基线是绿的；
2. 逐条核对审查意见：能写测试的先补测试，再改代码；
3. 合并后跑全量测试 + `node --check`，并在 `docs/REVIEW.md` 第 8 节记录「接受/拒绝 + 理由」；
4. 文档里的测试数、路线图同步更新；
5. 拒绝的意见要写清原因（口径不同、数据未知、会破坏兼容），不能静默丢掉。

## 4. 信箱文件

- `docs/REVIEW.md`：正式的复查结论与外部审查记录（只追加，不改历史条目）。
- `var/collab/`（运行时目录，不提交）：
  - `from-kimi.md`：外部审查放意见；
  - `to-kimi.md`：本会话放「已合并/待确认/需要你复核」的清单。
- 两边都不写对方的私密路径；只引用项目内相对路径。

## 5. 冲突时怎么办

- 数值/口径冲突：以 `packs/act2autochess/pack.json` 和 `docs/DATA_PACK.md` 的置信度标签为准，
  标 `assumed` 的一律不当成事实；
- 代码风格冲突：以现有代码为准（stdlib + numpy/Pillow，不引新依赖）；
- 一边有测试、一边没有：先合并测试，再决定实现。

## 6. 交接时的最小信息

无论哪边接手，先看这三样：

```bash
python scripts/check_all.py --frames var/demo_frames   # 一条命令跑完全部门禁
py -3 -m unittest discover -s tests     # 现在应该是 169 个全绿
py -3 -m covenant selftest             # 数据包/引擎自检
py -3 -m covenant demo --no-browser --port 8801
```

再打开 <http://127.0.0.1:8801/> 看对局页，`#stats` 看统计页，`/teach` 看教学页。

## 7. 主动用外部审查

本项目默认「多检查、多用外部审查」，不是等对方发现问题才动：

- 每轮重构/改行为后，在 `var/collab/to-kimi.md` 写清楚：改了什么、为什么、**请她重点看哪几处风险**、
  一条能复现的命令（`scripts/check_all.py`），并给出主目录路径（副本可能落后）。
- 她给的报告先按 `repro_bugs.py` 一类脚本复跑：**报告说的问题能复现才算数**；
  复现不了就在 `docs/REVIEW.md` 注明「快照过期/已修复」，并补一条回归测试钉住当前行为。
- 合并前跑 `check_all.py`；合并后同步测试数、路线图、`to-kimi.md` 的「已合并」清单。
- 双方都不直接改对方目录；以主目录为准，副本只用来出 diff/意见。
