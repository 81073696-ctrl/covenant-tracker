# 卫戍协议记牌器：独立插件操作台界面设计

日期：2026-11-07
状态：设计方向已获用户确认，等待书面规格复核

## 1. 目标

把现有偏通用数据后台的三列网页，迭代为具有独立桌面插件气质的“卫戍战术终端”。高频的商店、阵容和回合操作应当第一眼可见；概率、盟约、经济与日志仍可随时查看，但不再与主操作区争夺注意力。

本次是界面与信息架构迭代，不重写识别、记牌、概率、经济、存档或统计算法。

## 2. 已确认方向

采用“独立插件操作台”，不采用仅换肤的轻量方案，也不改成信息过度压缩的游戏悬浮 HUD。

视觉关键词：炭黑、暖金、冷青、切角、细刻度、状态灯、克制扫描纹理。风格服务于操作辨识度，不能牺牲中文可读性。

## 3. 范围

### 包含

- 对局页的信息层级、布局与视觉系统重做。
- 顶栏、状态摘要、商店、整备区、战场、概率与搜索、盟约、经济、日志的样式统一。
- 统计页和现有弹窗套用同一设计系统。
- 宽屏、普通桌面窗口和窄窗口的响应式布局。
- 键盘焦点、文字对比度、状态文本和减少动态效果的系统偏好支持。
- 前端回归测试、语法检查及真实页面验证。

### 不包含

- 新建 Electron、Tauri 或其他桌面壳工程。
- 修改后端 API 字段、存储格式和游戏规则。
- 新增付费、联网、账户、云同步功能。
- 改动图像识别模型、卡池计算或统计口径。
- 更换桌面快捷方式的启动方式；它继续打开现有本地服务。

## 4. 架构与边界

继续使用现有零构建前端：`covenant/ui/web/index.html`、`style.css` 和 `app.js`，数据仍来自现有快照与动作 API。

优先通过 HTML 分组和 CSS 完成改造。保留 `app.js` 依赖的元素 ID、表单字段、弹窗结构和事件语义；确需调整 DOM 时，同步核对所有选择器和事件绑定。不得以静态演示数据替代真实快照。

新增样式按层次组织：设计变量与基础元素、应用骨架、操作组件、业务模块、弹窗与统计、响应式与可访问性。避免通过大量 `!important` 或内联样式覆盖旧规则。

## 5. 页面结构

### 5.1 顶部指挥栏

- 左侧：品牌标识、“卫戍协议”名称、精简版本标识。
- 中部：对局／统计切换，以及模式选择。
- 右侧：连接状态、新局、自动识别、编辑商店、设置和教学入口。
- 自动识别必须同时用文本表达运行状态，不能只依赖状态灯颜色。
- 顶栏在桌面端保持紧凑；空间不足时允许功能区分行，不裁切按钮。

### 5.2 对局状态带

在顶栏下集中显示回合、资金、调度中心等级、生命和阶段。资金是当前最强的强调项；其余状态使用统一数字排版。

刷新、升级、过回合、锁定和摆一张形成主操作组，与状态带相邻。按钮保留实际费用或收益文本，禁用状态仍可读。

### 5.3 主工作区

宽屏采用“中央主操作区 + 右侧情报栏”，不再维持三个同权重列。

中央主操作区：

1. 商店为视觉主角，保留现有卡片数据、购买、Shift 编辑和确认商店操作。
2. 整备区与战场位于商店下方，采用清晰的区域标题、容量和空位样式。
3. 已上阵、已购买和可购买状态通过边框、徽记及文本共同表达。

右侧情报栏：

- 依次承载商店概率、搜索与干员表、盟约、经济、刷新实测和日志。
- 使用紧凑分节与局部滚动，避免整个页面被长表格撑得失去主操作上下文。
- 保留完整概率免责声明、实测样本提示和经济解释文本。
- 情报分节使用原生 `details`／`summary` 提供折叠，不引入额外状态管理；概率与盟约默认展开，其余分节默认展开且允许用户折叠。折叠只改变显示，不得清除数据或中断快照刷新。

### 5.4 统计与弹窗

统计页保留现有图表、筛选、账本和记录功能，统一标题、数字、表格、按钮及空状态样式。设置、编辑、教学等弹窗保持原有流程，增强焦点可见性、层级和移动端边距。

## 6. 视觉系统

- 背景：近黑炭色，面板比背景略亮，以细边框而非厚重阴影分层。
- 主强调色：暖金，用于当前回合、资金和主要操作。
- 次强调色：冷青，用于已连接、已激活和正向反馈。
- 危险与错误沿用明确的红色系，不与普通金色强调混淆。
- 字体：优先系统中文无衬线字体；数字使用等宽数字特性，不依赖外部字体下载。
- 切角和刻度只用于面板外框及装饰伪元素；正文、输入框和表格保持规整。
- 动效限于短促悬停、状态变化和折叠过渡；遵循 `prefers-reduced-motion`。
- 不使用影响识别的大面积辉光、持续闪烁或低对比度正文。

## 7. 响应式行为

- 宽屏（建议不小于 1280 px）：中央主操作区与右侧情报栏并列。
- 普通桌面窗口（约 900–1279 px）：缩窄情报栏并压缩非关键装饰，商店和阵容保持可用。
- 窄窗口（小于约 900 px）：改为单栏，状态摘要可换行，情报区自然排列在主操作区之后；不隐藏任何现有功能。
- 表格允许自身横向滚动，页面不得出现非预期整体横向滚动。
- 弹窗宽度受视口约束，内容可纵向滚动，关闭与确认操作始终可达。

## 8. 状态与错误处理

- 继续展示后端返回的连接、识别、样本不足、账本保存和导入错误，不在前端吞掉或美化成成功。
- 加载中保留上次有效数据，但必须有可辨认的更新状态；请求失败时保留用户上下文并显示错误。
- 空商店、空阵容、无刷新记录和无统计数据使用明确空状态，不伪造卡片或图表。
- 所有图标按钮保留可访问名称；颜色之外必须有文本、形状或边框提示。

## 9. 验证与验收

1. 现有 Python 测试与前端行为测试全部通过，新增必要的界面结构或交互回归测试。
2. `app.js` 语法检查、项目自检和 HTTP 冒烟通过。
3. 实际页面确认对局／统计切换、模式选择、新局、识别开关、商店编辑与确认、搜索、盟约、经济、日志及全部弹窗可用。
4. 在宽屏、普通桌面宽度和窄窗口检查：无功能消失、无按钮被遮挡、无整体横向溢出。
5. 控制台无新增 JavaScript 错误，快照更新后界面仍由真实数据驱动。
6. 同步到原项目前重新比较目标文件，保留 DeepSeek 的并发改动并先备份；不覆盖无关文件。

## 10. 完成标准

用户从桌面快捷方式进入后，看到统一的战术终端而非通用后台；商店和阵容是视觉中心，关键状态一眼可读，情报信息可快速扫描，原有功能和数据口径保持不变。
