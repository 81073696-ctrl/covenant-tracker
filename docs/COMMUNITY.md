# 把统计放到网上：社区收集器

卫戍协议没有官方战绩 API，所以「全服 pick 率」只能靠玩家自愿贡献记录。
本项目带了一个极小的收集器，自己一台机器就能跑，不需要数据库、不需要 Node。

```
玩家 A ──┐
玩家 B ──┼─ POST /api/submit ─→ 收集器（var/community.jsonl）─→ GET /api/stats ─→ 网页/面板
玩家 C ──┘
```

## 1. 起服务

```bat
py -3 -m covenant community --port 8900 --data var/community.jsonl
```

- 默认只监听 `127.0.0.1`，给本机或局域网调试；
- 要放到公网，先套 HTTPS 反代（Caddy / Nginx），再监听 `0.0.0.0`；
- 公网务必加 `--token`，否则任何人都能灌数据：

```bat
py -3 -m covenant community --host 0.0.0.0 --port 8900 --token 换成你的随机串
```

启动后浏览器打开 `http://<host>:8900/` 能看到一个极简排行榜，确认服务活着。

## 2. 上传本机记录

面板里也能直接传：统计页 →「上传到社区」→ 填地址（会记在 `var/community.json`，下次自动带出）
→ 看一眼提示的「本机 N 条」→ 点上传。服务端按记录 id 去重，重复点不会重复计数。
页面上还会显示令牌是否已保存；令牌只存在本机，不上传、不进日志。


```bat
py -3 -m covenant share --url http://127.0.0.1:8900
py -3 -m covenant share --url https://your.domain --token 换成你的随机串
```

或者从面板「统计 → 导出 CSV」拿到文件，让别人手动导入。

## 3. HTTP 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/` | 极简 HTML 排行榜（前 10 名） |
| GET | `/api/health` | `{ok, version, records}`，探活用 |
| GET | `/api/stats?mode=&band=&patch=&min=` | 与面板完全相同的聚合结果 |
| POST | `/api/submit` | `{"records":[...]}`，返回 `{added, skipped, bad, total}` |

约束：

- 单次最多 500 条、请求体上限 2 MB；
- 每 IP 每分钟最多 30 次提交（`_RateLimiter`）；
- 记录按 `id` 去重，重复上传不会重复计数；
- `bad` 是解析失败的行数，用来发现版本不匹配。

## 4. 隐私边界

记录里**没有**账号、设备、IP、对局时间之外的任何标识；`MatchRecord` 的字段就是
模式、策略、赛季、回合、生命、结果、杯数、终局阵容、盟约、备注。备注是玩家自己写的，
默认空。收集器不写访问日志（`log_message` 被关掉）。

如果以后要做账号体系，也应该只用于「防止一个人刷票」，而不是把记录和身份绑定。

## 5. 规模化时要注意什么

现在的实现是**单进程 + 一个 JSONL 文件**，几千到几万条记录没问题（全量读入内存聚合）。
再往上：

1. 把 `RecordBank.records()` 换成 SQLite（`SELECT` 聚合），接口不变；
2. `/api/stats` 已经是「按参数缓存 15 秒」的结构，换 Redis 只是替换 `_cache`；
3. 反代层加 gzip 与 `Cache-Control`，`/api/stats` 的结果天然适合缓存；
4. 记录格式带 `v` 字段（当前 2），以后加字段要兼容旧记录。

## 6. 常见问题

**Q：为什么服务端算出来的干员名是 id？**
`--pack-dir` 指向的目录里没有数据包时会退化成 id。把 `packs/` 一起部署即可。

**Q：能只收「通关」的局吗？**
不建议。只收通关会让通关率永远 100%。要么全收，要么明确标注筛选口径。

**Q：需要用户登录吗？**
当前不需要，也不建议一开始就做。先看有多少人愿意传，再决定要不要防刷。
