# 维护者交接说明

## 一句话现状

这是一个**核心计算较完整、手工功能可用、视觉自动化仍处于原型阶段**的项目。原作者不再独立持续开发，公开仓库用于寻找维护者和社区贡献者。

## 已经具备

- 外置数据包、共享卡池余量、独立格商店概率、经济与盟约计算；
- 新局、购买、出售、刷新、升级、过回合、三合一和手工纠错；
- 本地网页与 Windows WebView 桌面窗口；
- 数字、商店、单位、星级和结算模板的后端接口；
- 多识别配置、逐帧稳定门控、事件账本、刷新记录和战绩统计；
- `/lens` 诊断台，以及 `tools/screen-lens/` 独立诊断工具；
- 单元测试、前端语法检查、数据包自检和私服回放脚本。

## 没有做到什么

- **不是正式服开箱即用插件。** 官方客户端的 UI 尚未完成系统校准。
- **不是零配置全自动导入。** 新字体、皮肤、卡面和单位通常需要人工教学。
- 装备、多人共享池、完整星级、杯数和最终等级识别尚未完成。
- 当前布局与模板更偏向单格／少量单位测试，不能据此宣称所有整备区与战场位置均已覆盖。
- 自动识别错误可能影响状态；请保留手工纠错，不要为了“认出来”而盲目降低阈值。
- 私服是第三方复刻，私服结果不等于官方客户端结果。

## 最近的动态私服观察

这些是有针对性的局部回归，不是完整覆盖率认证：

- 资金、等级、回合和生命在已校准的 L1 场景中可与 DOM 真值一致；
- 已学习商店可以同步，新干员仍依赖模板教学；
- 购买造成的资金下降和已售出格曾被正确同步；
- 付费刷新已有“跨帧资金证据 + 商店变化”的回归测试；
- **免费刷新仍需修复**：观察到商店发生变化但资金不变时，可能无法形成完整记录；
- 单位识别与提交之间受稳定帧门控影响，端到端测试必须条件等待，不能只固定等待几秒。

## Screen Lens 的正确接法

统一保存四类证据：原帧、DOM／人工真值、插件快照、诊断报告与断言。推荐每次失败都保留这组数据。

**必须使用与插件相同的整窗帧（例如 `/api/frame`）做诊断。** 浏览器 CDP 的 viewport 截图可能不含标题栏；即使比例坐标相同，也会产生纵向错位，导致误判模板或区域。

Screen Lens 负责解释“为什么认出／认不出”，不负责替代 `CaptureService`、`FollowGate`、reducer 和账本回归。教学会写模板，所谓只读是指不修改游戏或对局状态，不是完全不写配置。

## 建议接手顺序

1. 跑通 `scripts/check_all.py` 与 demo，建立 CI。
2. 用可公开的合成／私服帧建立标准回归集，覆盖 HUD、商店、已售出、免费／付费刷新、上阵和撤回。
3. 先修免费刷新和未知格教学队列，再扩大单位／星级覆盖。
4. 官方 UI 校准后，把每套皮肤／布局保存为独立 profile，不覆盖他人模板。
5. 最后再考虑发布 exe；发布包需要另做干净环境验收。

## 项目边界

只读屏幕，不读内存、不注入、不修改客户端。不要引入自动操作正式服或规避反作弊的功能。
