# 卫戍协议 · 记牌器 —— 项目归档

> 公开整理说明：本文保留 2026-11-07 归档时的历史判断与测试记录，不构成正式服能力认证。文中提及的私服参考数据、本机存档和过程截图均未公开；当前许可以根目录 `LICENSE` 为准，取舍见 [公开归档说明](ARCHIVE.md)。

归档日期：2026-11-07
最后版本：v1.0.0

## 它是什么

给《明日方舟》「卫戍协议：盟约」用的桌面伴生工具：卡池余量、商店命中概率、
经济/升级规划、盟约层数、对局记录与统计，以及可选的屏幕识别。

只读屏幕，不读内存、不改游戏、不自动操作。

## 为什么停

核心矛盾是**数据来源**：

- 明日方舟没有对局 API，PC 客户端不提供可读日志；
- 棋盘是 3D 的、镜头可缩放平移，整备区还要打开面板；
- 纯视觉在「固定 UI + 固定分辨率」下可行，但每次 UI/镜头变化都要重标，
  维护成本高于工具本身的价值。

私服那条线证明识别链路能跑通，但验证不了官方客户端；继续投入的期望收益 < 成本。

## 实际做到哪一步

- `python -m unittest discover -s tests` → **224 tests OK**
- 数据包 `packs/act2autochess-private`：219 干员 / 23 盟约 / 43 策略 / 11 模式
- 私服回放帧：HUD 120/120，商店 72/76（0 错认，4 unknown）
- 手动记牌：买卖/刷新/升级/过回合、卡池扣减、三合一、盟约阈值、经济曲线
- 统计：对局记录、pick/通关率、Wilson 区间、按回合时间线、JSONL/CSV 导入导出
- 社区：自托管收集器 + `covenant share`（可选）
- 桌面壳：`py -3 -m covenant serve --desktop`
- 识别诊断台：`/lens`（后抽成独立工具 `screen-lens/`）

## 没打通

- 官方客户端：数字模板只有 1/2/3/4/8；固定区域在非 16:9/非 1600×900 下会偏；
  3D 战场单位没有可靠检测。
- 换皮肤：profile 机制在，但每套皮肤仍需重学数字/结算。
- 打包 exe / 托盘 / 设置页能用，但没有面向小白的安装器。

## 可复用资产

- `covenant/calc/`：卡池、独立格概率、经济曲线、盟约阈值（纯函数）
- `covenant/state/`：绝对快照 + 动作/观测分离 + 事件账本（可重放）
- `covenant/stats/`：记录模型、去重、聚合、Wilson、导入导出
- `screen-lens/`：独立的「截图 → 结构」诊断工具（MIT，可单独发布）
- `refs/stronghold`：社区逆向数据（GPL 来源，仅参考）
- `refs/private`：私服数据，仅本地研究，不要分发

## 如果捡起来

最小路线（不碰 3D 棋盘）：

1. 只做 HUD 数字 + 商店面板两条粗带；整备/战场手动点选；
2. 用 2–3 张目标分辨率截图，在 `/lens` 补 0–9 与卡面模板；
3. 把 `params.auto`（粗带自动切格）接进插件，替换写死的 `slots`；
4. 攻略助手另起：`comps.json` + 抓位页，完全不依赖屏幕。
